# Decision records

This directory explains why operating rules exist. Each file contains one ruling,
the evidence or failure behind it, and the evidence needed to reconsider it.
The issue tracker holds active work and deliberation; these records preserve settled
reasons. A memory store may point here without becoming another decision ledger.

Before proposing a change, search this directory for an existing ruling. A new
proposal must answer the recorded reason, not merely argue against the old rule.
Record a reversal in a new file and leave the earlier record readable.

File one ruling in `YYYY-MM-DD-<slug>.md` when a decision is reached, an approach
is retired, or a failure creates a rule for later work. Use the decision day, an
ASCII slug, and a unique basename. When only the month is known, use day `01` as
a filename sort key and put only `YYYY-MM` after `Decided:`. Search for the same
fact before filing: each ruling has one home, while other documents link to it.
