# Vault MCP patch

This is a code-only patch against [obsidian-mcp](https://github.com/lstpsche/obsidian-mcp), licensed MIT upstream. The patch is for the upstream 2.5.0 code base. Apply [local-changes.patch](local-changes.patch) in a separate checkout. It adds connect-time instructions from `OBSIDIAN_INSTRUCTIONS_FILE` or `OBSIDIAN_INSTRUCTIONS`, honors the configured tool filter over HTTP, drops read-side watcher events, speeds exact path lookup, and requires a bearer token on `/mcp` when `OBSIDIAN_HTTP_TOKENS_FILE` is set. An unreadable, empty, or short token file prevents startup; `/health` remains open. The [client instructions example](instructions.example.md) summarizes the vault layout and rules. Edits to the instructions file are picked up at each client initialize.

Build on the target machine when its C library differs from the development machine. In a checkout of the matching upstream tag, apply the patch, run `cargo test --lib` and `cargo test --test integration_tests` with a separate writable target directory, then `cargo build --release`. Keep semantic search out of `OBSIDIAN_TOOLS` until the semantic daemon build and connection timeout are validated together. A daemon without an embedding backend returned errors, and a long vault initialization exceeded the client timeout.

Test the new binary on a side port with a separate `OBSIDIAN_MCP_DATA`, a throwaway token file, and a test vault. Probe initialize, tools/list, note_read, a denied tool, missing-token 401, wrong-token 401, and accepted-token access. Never let a side test share the active index directory. Install a backup of the current binary, install the new one, restart `brain-mcp`, wait for the endpoint, and repeat the probes. If rollback crosses the bearer patch, restore the binary and the matching systemd and proxy authorization configuration together. A local listener behind a proxy still needs the bearer gate: another local user could otherwise reach it directly.

The [systemd templates](../deploy/) use placeholders documented in their filenames and a credential drop-in. The proxy and server token files must contain the same long token if the proxy substitutes an upstream Authorization header. Rotate both and restart the server after changing them. Restrict the server to a dedicated user when other local processes must not read its credential.
