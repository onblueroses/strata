# Vault client instructions

Read `AGENTS.md` from the vault root before writing. The numbered folders are the human-facing records; `9 Agents/` is agent apparatus. Use the section matching the fact, and make one canonical record with links from other notes. The vault holds durable knowledge; the issue tracker holds open work.

Use Markdown frontmatter with `schema`, `type`, `title`, `source`, `date`, and `author`. Sign writes as `(agent/member, date)` where the record calls for a log signature. Keep person and organization cards unique; append contact history and do not let status regress. A substantive interaction has a conversation card; a call note links its calendar event. A self-reported `where` outranks event-derived `doing_at` in a member's current-status record.

New captures go to `5 Inbox/captures/` and are filed daily. Unknown root folders are swept there after a quiet period. Never put a credential or signed URL in a vault file. Read back writes from the server copy before reporting completion. Tool access does not itself grant authority to send, publish, spend, change schema, or delete.
