# Bend privacy policy

Policy.bend defines scan planning, target aggregation, and final verdicts. LAWS.bend states the invariants; PROOF.bend proves them against the policy. build.sh proves and compiles the finite policy into the checked-in shell table used by the Claude gates. Runtime verdicts use Bash builtins and do not launch Bend. A clean scan permits only when its reported evidence class covers the requested plan. Findings, missing evidence, failed scans, and uncertain target visibility refuse under the policy.

From the repository root, run `bend guide` before changing the Bend sources, then `bend claude/hooks/privacy-decision/PROOF.bend` and `bash claude/hooks/privacy-decision/build.sh --check`. Run `python3 claude/hooks/privacy-decision/test-integration.py`, `python3 claude/hooks/privacy-decision/test-staged.py`, `python3 claude/gates/tests/test-privacy-event.py`, and `bash claude/gates/tests/test-privacy-gates.sh` for the policy, staged snapshot, event decoder, and real gate boundaries. The tests use scratch repositories and do not call a model provider.

The staged checker freezes the Git index before building and testing. It refuses changed or removed existing law claims without the owner's explicit requirement-change marker, rejects unsafe proof holes and duplicate imports, and checks generated-table freshness. A local pre-commit hook may call `python3 claude/hooks/privacy-decision/check-staged.py`; the hook never stages files. Build and test artifacts stay under an ignored local scratch directory.

The laws cover the stated finite policy, not shell command recognition, Git range selection, file reads, token inventory, or every form of publication. The fixture suite checks those boundaries separately, including positive controls that prove the detectors can see their targets. A local filesystem destination assumes the owner treats that repository as private; a private SSH destination requires an exact local pin and an unchanged proxy-free mapping. The opt-out for an explicitly reviewed command is the leading `PRIVACY_ACK=1` assignment. See [maintenance notes](../MAINTENANCE.md) for the rulings and failure history behind these checks.
