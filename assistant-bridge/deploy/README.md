# Deployment interface

These systemd unit templates and [env.example](env.example) show the server contract. Replace every `@NAME@` token in the units with the matching site value before installing them. `BRIDGE_CONFIG_DIR/bridge.env` is root-owned, outside the Git worktree, and contains paths and public identifiers only. Put tokens in separate mode-0600 regular files. Provide a site-owned `bridge-alarm@.service` for the check unit's `OnFailure` page.

Run the jobs from a root-owned copy of the reviewed `tools/`, `AGENTS.md`, `ASSISTANT.md`, and `bridge-policy.toml`. The Git worktree is never executable authority. The responder's rules directory contains the reviewed rules. The responder runs `codex exec` under its own unprivileged OS user and its own subscription login; do not copy another user's Codex login because the copies can invalidate each other's refresh token.

Before each installation, fetch `origin/main` through the operator-controlled deploy path and run `verify-reviewed.sh <reviewed-commit> <root-controlled-DEPLOYED_REV>`, with `BRIDGE_OWNER_NAME` set to the owner's Git commit identity. It refuses an unknown deployed revision, a non-descendant, differing control files on `origin/main`, or a control change attributed to anyone else since the deployed revision. Stage files with `git show <reviewed-commit>:<path>`, never from the worktree. Keep the returned full revision in `DEPLOYED_REV` only after installation and smoke checks succeed. A first installation needs an owner-reviewed baseline `DEPLOYED_REV`; do not skip the authorship check. Git author and committer fields are the source deployment's check, so the operator must also review the commit chain; those fields alone are forgeable.

Install the rendered unit files under `/etc/systemd/system/`, the reviewed executable bundle under `BRIDGE_EXEC_DIR`, and the reviewed rules under `BRIDGE_RULES_DIR`. Make the vault user's state and lock writable only by that user; keep the responder state and rules root-controlled. A root-owned private-repository attestation at `BRIDGE_VISIBILITY_ATTESTATION` binds the exact remote URL and is renewed after identity or visibility changes. Publish and apply also check GitHub visibility on each run.

Run publish once, apply and respond in dry-run mode, then enable only the timers whose checks passed. Run check once. A pause marker makes a job exit successfully without doing work; inspect the marker directory before interpreting a dry run. `bridge-check` does not enable timers, so a stopped timer pages through the site alarm. systemd 255 may print a timer's `LastTriggerUSec` in human form even with `--timestamp=unix`; avoid parsing that display as an epoch. After a large vault history rewrite, a pre-push scanner may time out; require a separate manual scan before any bypass. A policy change on `main` stops publish until the reviewed bundle is deployed.

The [operations guide](../tools/README.md) has the behavior and recovery details. Publish produces the configured repository's `vault/` tree from the vault itself.
