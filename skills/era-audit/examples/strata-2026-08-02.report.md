## What ships

The skill separates facts from priors:

- `scripts/probe_ground_truth.py` observes the platform, selected executables on `PATH`, symbolic lane bindings and wrappers, and optionally live MCP-list responses. It validates a filled-or-unknown result.
- `ground-truth.template.json` asks for what a probe cannot know: reader behavior, runtime capabilities, the authoritative memory system, retired systems, delegation contracts, house standards, prompting rules, and incident history. Unknown is valid.
- `examples/ground-truth-2026-07-30.example.json` is a dated, one-install worked example. It is not a default.
- `references/pattern-prior-2026-07-30.md` carries the 17 install-agnostic patterns derived from 272 findings across 69 files. It tells the operator to re-derive them before trusting them.
- `scripts/era_audit.py` freezes sources and ground truth, balances batches, runs read-only schema-constrained auditors, rejects missing or duplicate dispositions, and rejects non-verbatim quotes.
- `findings.schema.json`, `scripts/validate_findings.py`, and `scripts/brief.py` make the output checkable and readable.
- `references/remediation.md` preserves the fixer, independent verifier, collateral-deletion critic, premise verification, and stated stop gate. It does not prescribe a converge-to-zero loop.

The current probe produced 12 fact fields and left `known_incidents` unknown. It observed 30 operator-selected executable names, four placeholder model-lane bindings, and live MCP-list responses. Presence is not capability: the probe does not infer command syntax from an executable name or infer in-process tools from a subprocess. Reader strengths, house rules, retirement dates, memory authority, and incident provenance need a declaration with evidence or remain unknown.

## Findings I would fix first

### [P0] Run every Codex reviewer in a read-only sandbox

Files: `commands/review.md:64-73`, `commands/review.md:405-408`, `commands/verify.md:140-143`, and `skills/codex-review/SKILL.md:194-203`.

Failure mode: each review path passes `--dangerously-bypass-approvals-and-sandbox`. The local CLI describes that flag as extremely dangerous and intended only for an externally sandboxed environment. These commands run directly in the target repository, so a reviewer can mutate the worktree or act on prompt injection from reviewed content while the surrounding prose falsely calls it read-only.

Fix: replace the bypass flag with `--sandbox read-only`; use `--ephemeral` for `codex exec`. Keep a deadline only when its value has a measured or operator-selected basis.

### [P0] Treat unknown repository visibility as public

File: `commands/review.md:103-114`.

Failure mode: an authentication, network, or `gh` error is treated as proof that a repository is private, which disables public-repository privacy checks. That can publish identifiers precisely when visibility could not be established.

Fix: keep a three-state result. `false` is public, `true` is private, and every failed or unexpected probe is unknown. Run the public privacy checks conservatively for unknown.

### [P1] Stop routing browser work to absent surfaces

Files: `skills/browser-use/SKILL.md:3-5`, `skills/browser-use/SKILL.md:53-68`, `skills/mobile-preview/SKILL.md:13-18`, `skills/mobile-preview/SKILL.md:56-112`, `commands/ship.md:44-53`, and `skills/frontend-design/SKILL.md:304`.

Failure mode: the live probe found no `browser-use` executable and no Playwright MCP server, yet the activation text and workflows select both. `playwright` and `browser-task` executables do resolve, but their compatible command contracts are unknown.

Fix: probe before routing. Use a backend only after its executable or MCP server responds and its live help supports the needed operation. Preserve the login-session, viewport-reset, before/after, and visual-inspection requirements.

### [P1] Give the harness a hard resource boundary

File: `skills/harness/SKILL.md:49`, `skills/harness/SKILL.md:768-806`, and `skills/harness/SKILL.md:899-907`.

Failure mode: the harness warns after a hard-coded token count, then explicitly keeps iterating until convergence or a later escalation. Convergence signals bound quality behavior, not spend; the current defaults and strike counts have no recorded measurement or owner requirement.

Fix: require an owner-selected hard pause budget and keep convergence detectors separately. Use exact token telemetry when exposed; otherwise record token use as unknown and enforce a measurable wall-time or spend budget.

### [P1] Fall back inline when symbolic lanes are unbound

Files: `CLAUDE.md:15-25` and `config/model-map.toml:1-8`.

Failure mode: the root doctrine makes delegation the usual move and routes work to four symbolic lanes, while every current binding is a placeholder rejected by the wrapper. A fresh or unconfigured install therefore points its default workflow at paths that cannot run.

Fix: retain the lane setup flow, but make the live routing rule conditional on a successful binding preflight. Use the running agent or verified direct runner when no lane resolves.

Exact outside-file requests are collected in `skills/era-audit/INTEGRATION.md`.
