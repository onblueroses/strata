# Dispatcher

`dispatcher.py` is the one claimer for the issue team configured by `DISPATCHER_TEAM_KEY`. It tails the webhook event log and polls Linear every five minutes. It claims eligible tickets with exactly one `for:codex` or `for:claude` label, respects `laptop` and `vps` pins, and launches a fresh worker over forced-command SSH. Codex can run on either machine; Claude Code with @Chrome runs on the laptop. Ticket text does not determine the route.

A claim posts an authenticated `Starting run-xxxxxx` comment and moves the ticket In Progress. A worker posts signed milestones and one signed outcome. The dispatcher accepts completion only from that run's signed comment with a matching authenticated Linear author in the root-managed `worker-identities.json` policy. It hands a missing outcome back; a repeat routes to `for:operator`. An unsigned reply inside the 14-day window or a validated phone approval starts a follow-up. A later reply during a run is covered when the outcome postdates it. The dispatcher waits for an unreachable laptop without consuming the attempt or approval. A poll sweeps claims interrupted before launch.

`worker-run` validates a single `run <ticket> <run-id> <engine> <seconds>` command, takes the brief and ticket packet on stdin, and writes a receipt and last message. The SSH key's `authorized_keys` forced command is its entire dispatch power. `KillMode=process` allows active SSH children to finish across service restarts, then the dispatcher adopts them by pid. `BRIEF.md` and its machine and engine supplements define worker conduct. The shared ticket convention is [followup-convention.md](../../reference/followup-convention.md).

Configure the service from [env.example](deploy/env.example), the runner from [worker.env.example](deploy/worker.env.example), the SSH restriction from [authorized_keys.example](deploy/authorized_keys.example), and the authenticated signature policy from [worker-identities.example.json](deploy/worker-identities.example.json). The Linear OAuth app secret and SSH key belong in protected runtime files. `DISPATCHER_ALLOW` limits claims to listed canary tickets. A tracker 401 between claim and launch is handled from the claim already posted and later reconciliation. Do not run `brain-linear` as the dispatcher account while the service runs: each call revokes that app's token, invalidating concurrent service calls.

Run offline tests with `python3 -m unittest discover -s work/dispatcher -p 'test_*.py'` from the repo root. The units in [deploy](deploy/) are examples; set local accounts, paths and hosts before installation.
