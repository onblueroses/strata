# Approval gate

`approve-gate` is the phone page for a worker's exact `APPROVAL NEEDED:` action. It finds open asks in Linear, verifies the signed comment against an authenticated Linear author in the shared root-owned worker identity policy, and shows the action on the phone. A tap writes a durable record keyed by the source comment ID. The dispatcher consumes that record only if the ticket, comment and action still match its stored ask. A changed or closed ask cannot be approved by an old record.

The service binds to the tailnet and admits only configured phone addresses and Host headers. The general dashboard also verifies the phone's tailnet node and user identity. JSON posts require a same-origin check and an application header; a double tap confirms the exact decision. Pushes through ntfy are content free. The `task_scopes` mode is present in code but disabled by default; ordinary actions use the exact ask line and record.

Set local paths and phone identity in [config.example.json](config.example.json) and [env.example](env.example); protect the Linear key, ntfy topic and identity policy outside this tree. The static dashboard is in [dashboard](dashboard/). The installer checks the reviewed [task-policy hash](task_approval.sha256) before transfer, retains the previous package, restores it on a failed install or restart, and reads back service health and the installed files. Run offline tests with `python3 -m unittest discover -s work/approve-gate -p 'test_*.py'`; `test_deploy.sh` runs the installer's remote half under stubs and checks that a failed restart restores the previous package. See [the work system](../README.md) for the four tap-only gates and destruction tiers.
