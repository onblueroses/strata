# Follow-up Convention

Use the operator-supplied task ledger for work that needs an owner, coordination, a decision, or follow-through beyond the conversation. Keep passing ideas, quick questions, and small self-contained tasks in the conversation.

Before claiming existing work, read its current owner, status, labels, relations, and recent comments. Preserve unrelated metadata, use one routing label where the ledger requires it, and append a signed start note with the concrete scope and session identifier. A claim coordinates work; it is not an exclusive file lock.

Recheck the ledger and working tree after a handoff or interruption. Append outcomes rather than editing history. Close only completed work. Leave unfinished work open with enough context for another operator to resume. File unresolved decisions and material deferrals; do not create tracking work for routine status.

The ledger's CLI, workspace, labels, and identifiers are operator-supplied. This snapshot provides the contract and intentionally invents no runnable private commands.
